# ريزونكس — موقع المكتب ونظام الإدارة ومساعد ريزونكس

تطبيق Next.js عربي يضم:

- **الموقع العام** `/`: الخدمات وحجز الاستشارة.
- **نظام المكتب** `/app`: العملاء، القضايا، الجلسات، الأحكام، المستندات والإصدارات، المسودات والقوالب، واتساب والتذكيرات، المهام، طلبات الاستشارة، الأتعاب والفواتير، المكتبة القانونية، التقارير، الإعدادات، سجل التدقيق، سجل الوكلاء، سلة المحذوفات.
- **مساعد ريزونكس** `/app/assistant`: وكيل مبني على Claude ومربوط بقاعدة بيانات المكتب.
- **توزيع الملفات** `/app/intake`: وكيل يقرأ PDF وWord والصور ويقترح الربط بالعملاء، ولا يحفظ شيئاً قبل المراجعة.
- **بوابة العميل** `/portal`: دخول برمز واتساب، وتعرض حالة القضية وجلساتها فقط.

لا يرسل النظام شيئاً لعميل دون اعتماد، إلا قالب تذكير فعّل المحامي إرساله التلقائي بنفسه. مدد الطعن لا تعيش في الكود: يكتبها المحامي كقواعد، وناتجها مقترح لا أثر له حتى يؤكده.

## الهوية البصرية

ريزونكس = شبكة عُقد بنفسجية على عدم أسود، مع ذهبي محصور في أزرار الفعل الأساسية.
كل الألوان تمر عبر التوكنات في أعلى [globals.css](src/app/globals.css)، فتغييرها هناك يعيد
جلد الموقع العام والنظام الداخلي معاً. الشعار في [brand.tsx](src/components/brand.tsx)
(الاسم `ScaleLogo` محفوظ لأن كل الشاشات تستدعيه).

بورتريه المكتب الافتراضي [reasonix-portrait.svg](public/images/reasonix-portrait.svg)
مولّد برمجياً: شكل بشري يتحوّل إلى سحابة عُقد. يُستبدل بصورة المكتب الحقيقية من الإعدادات.

**شخصية العرض خيالية**: «المحامي نديم الصفدي» وبيانات `db:demo` كلها من نسج الخيال،
لعرض النظام فقط. تُحذف قبل إدخال أي بيانات حقيقية.

## التشغيل محلياً (هذه النسخة)

قاعدة هذا المكتب مستقلة تماماً عن مكتب حمزة ومكتب علاء: منفذ `54331`، قاعدة `reasonix`،
ومجلد بيانات `~/.reasonix-local-db`. لا يتقاطع تشغيلها مع أي مكتب آخر.

```powershell
npm install
npm run db:local      # يشغّل قاعدة التطوير على 54331
npm run db:deploy
npm run db:demo       # بيانات خيالية للعرض
npm run dev
```

الدخول: `owner@reasonix.local` / `Reasonix-Local-2026` (من `.env`).
وحسابان آخران بنفس كلمة المرور: `trainee@reasonix.local` و`secretary@reasonix.local`.

## التشغيل

المتطلبات: Node.js 20 أو أحدث. ثبّت الحزم بـ `npm install`، ثم اختر إحدى طريقتي القاعدة.

**خادم PostgreSQL مثبّت** (جهاز جديد، بعد التأكد من عدم وجود `.env` أو قاعدة باسم `reasonix`):

```powershell
.\scripts\setup-database.ps1
```

يطلب كلمة مرور مسؤول PostgreSQL محلياً دون حفظها، وينشئ قاعدة `reasonix` ومستخدم تشغيل مستقلاً، ثم يطبق الترحيلات وينشئ حساب المحامي صاحب المكتب. تحفظ بيانات الاتصال في `.env` المستثنى من Git. إذا انقطع بعد إنشاء `.env`، تحقق أن القاعدة خاصة بهذا التطبيق، ثم استأنف بـ `npm run db:generate` و`npm run db:deploy` و`npm run db:seed`.

**قاعدة تطوير مستقلة** (ويندوز، لا تحتاج أي خادم مثبّت ولا تمس خادمك):

```powershell
# ضع في .env:
# DATABASE_URL="postgresql://reasonix:reasonix-local@localhost:54331/reasonix?schema=public"
npm run db:local
npm run db:deploy
npm run db:seed
```

تحفظ بياناتها في `~/.reasonix-local-db`، وتتوقف بـ `npm run db:local:stop`. ملف `.env` الحالي في هذا المجلد يستخدم هذه الطريقة.

بعدها شغّل `npm run dev`، وأضف مفتاح الذكاء الاصطناعي ورقم واتساب المكتب وموقعه من الإعدادات. يقبل الحقل مفتاح Anthropic أو Cohere أو OpenAI أو Gemini أو Groq أو OpenRouter أو xAI أو DeepSeek أو Mistral، ويتعرف على المزود ويتحقق من المفتاح عند الحفظ. يُحفظ مشفّراً ولا يُعرض بعد الحفظ، ويتقدم على `ANTHROPIC_API_KEY` إن وُجد. تغيير المزود يوقف الذكاء الاصطناعي حتى يوافق المحامي من جديد. قراءة PDF الممسوح تحتاج Claude، وقراءة الصور تحتاج مزوداً يدعم الرؤية.

لتجربة النظام ببيانات وهمية استخدم `npm run db:demo` بدل `db:seed`. ينشئ قضايا خيالية وحسابين إضافيين بنفس كلمة المرور: `trainee@reasonix.local` و`secretary@reasonix.local`، ويرفض العمل إذا كانت القاعدة تحتوي قضايا.

## كيف يعمل المساعد

```
سؤال المحامي → Claude → أدوات المكتب → إجابة مع مصادر، أو مسودة للمراجعة
```

- **الأدوات** في [src/lib/assistant/tools.ts](src/lib/assistant/tools.ts): البحث عن قضية أو عميل، قراءة ملف القضية، الجلسات، البحث في المستندات، قراءة صفحة، حفظ مسودة قانونية، حفظ مسودة واتساب.
- **الصلاحيات**: كل أداة تعمل بهوية المستخدم عبر `withDatabaseAccess`، فلا يرى المساعد إلا ما يراه هذا المستخدم. الرقم الوطني والأتعاب لا تصل إلى Claude إطلاقاً، والملاحظات الخاصة تصل فقط لمن يملك صلاحيتها.
- **المصادر الموثقة**: تعطي الأدوات كل سجل رقماً مثل `S3`، ويستبعد الخادم أي رقم لم تُرجعه أداة في السؤال نفسه ([agent.ts](src/lib/assistant/agent.ts)). الإجابة بلا مصدر تظهر معها ملاحظة واضحة.
- **التشريعات الأردنية الرسمية**: شغّل `npm run db:deploy` ثم `npx playwright install chromium` ثم `npm run laws:sync`. يجلب المستورد كل النتائج المتاحة في البحث الرسمي، بما فيها النافذ وغير النافذ، بسرعة محدودة، ويستأنف بعد الانقطاع. لا يعلن الاكتمال إلا بعد مطابقة عدد السجلات الرسمية والمستوردة. يعرض كل سجل رابط المصدر الرسمي وتاريخ آخر تحقق؛ راجع المصدر الرسمي قبل الاعتماد القانوني.
- **دون إجراء تلقائي**: الوكيل لا يملك إلا الحفظ كمسودة. الاعتماد للمحامي صاحب المكتب وحده، ويفرضه الخادم وسياسات قاعدة البيانات معاً.
- **المستندات بيانات لا تعليمات**: نص الملفات يُعامل كمادة للقراءة، حتى لا يوجّه ملف من الخصم عمل المساعد.
- **قراءة الملفات**: يُستخرج نص PDF صفحة بصفحة ونص Word بأقسام. الصور والملفات الممسوحة وPDF العربي المخزن بأشكال حروف معكوسة يقرؤها Claude، فتحتاج المفتاح وتفعيل الذكاء الاصطناعي من الإعدادات. بدونهما يبقى الملف محفوظاً دون نص.
- **موافقة صريحة**: المفتاح وحده لا يكفي. الذكاء الاصطناعي متوقف حتى يفعّله المحامي صاحب المكتب من الإعدادات.
- **منع الهلوسة**: مخرجات وكيل التوزيع تمر عبر مخطط صارم، وأي قيمة لا يوجد اقتباسها في الملف تُحذف. المسودة بلا مصدر تُرفض. أي تاريخ أو رقم دعوى أو مادة في الإجابة لا يطابق نتائج الأدوات يظهر كتحذير. المواد القانونية تأتي من المكتبة فقط.
- **سجل الوكلاء**: كل استدعاء يُسجل بمدخله ومخرجه ومستخدمه، في جدول لا يقبل التعديل.

## المصاريف وساعات العمل

- **المصاريف** (رسوم محكمة، طوابع، خبرة...) تُسجَّل من صفحة القضية، للمحامي صاحب المكتب والسكرتير. لكل مصروف خيار: يُفوتر للعميل أو على المكتب.
- **ساعات العمل** يسجّلها كل موظف لنفسه من صفحة القضية، ولا يرى ساعات غيره إلا المحامي صاحب المكتب.
- **الفوترة**: عند إنشاء فاتورة يمكن إضافة المصاريف غير المفوترة، والساعات بسعر ساعة يحدده المحامي. تُربط السجلات بالفاتورة فلا تُفوتر مرتين، وحذف الفاتورة يعيدها غير مفوترة. ما يُضاف منها لا يُحسب من الأتعاب المتفق عليها.
- قسما «المصاريف» و«ساعات العمل» في صفحة الأتعاب يعرضان كل السجلات عبر القضايا.

## نسيت كلمة المرور

- المحامي صاحب المكتب يعيّن كلمة مرور جديدة لأي موظف من «الإعدادات ← فريق المكتب». يُسجَّل خروج الموظف من كل أجهزته.
- لصاحب المكتب نفسه، على الخادم: `npm run reset-password -- البريد [كلمة-المرور]`. بلا كلمة مرور يولّد واحدة عشوائية ويطبعها. على Railway (لا يوجد `.env`) شغّل من سطر أوامر الخدمة: `node scripts/reset-password.mjs البريد`.

## الأدوار

- **المحامي صاحب المكتب**: كل الصلاحيات، وهو وحده يعتمد المسودات ورسائل واتساب ويسجل الأحكام.
- **المحامي المتدرب**: القضايا المسندة إليه فقط، وينشئ مسودات ومهام لنفسه.
- **السكرتير**: كل القضايا، الجلسات، العملاء، طلبات الاستشارة، دون الرقم الوطني والملاحظات الخاصة والأتعاب.
- **العميل**: يدخل برمز على هاتفه، ويرى حالة قضيته وجلساتها فقط.

سياسات RLS في `prisma/migrations/20261101210000_row_level_security`. يتجاوزها PostgreSQL لأي دور SUPERUSER أو BYPASSRLS. في الإنتاج استخدم اتصالاً مشفراً، وحساب ترحيلات منفصلاً، وحساب تشغيل لا يملك تعطيل RLS أو تعديل سجل التدقيق.

## مطلوب قبل إدخال بيانات حقيقية

- موافقة المكتب على إرسال محتوى الملفات إلى Anthropic، ومراجعة التزامات سرية المهنة وشروط الاحتفاظ بالبيانات.
- مراجعة نصوص الموقع العام والصورة التي يختارها المكتب مع قواعد نقابة المحامين بشأن الإعلان.
- إضافة واتساب المكتب وعنوانه وموقعه من الإعدادات. نصوص «عن المكتب» و«فريقنا» عامة وتحتاج صياغة المكتب.
- اعتماد سياسات المكتب لتحديد حقول الملاحظات السرية والأدوار المخوّلة بها.
- الرقم الوطني والملاحظات الخاصة مشفرة بـ AES-256-GCM. نص المستندات والأسماء غير مشفر على مستوى الحقل، ويعتمد على تشفير قرص الاستضافة، فتأكد منه. المستندات تُحفظ داخل قاعدة البيانات.
- اعتماد قوالب واتساب في Meta وكتابة أسمائها في الإعدادات. بدون بيانات الربط يبقى الإرسال يدوياً من `wa.me`، وبوابة العميل لا تعمل في الإنتاج.
- إدخال قواعد مواعيد الطعن بسندها القانوني، والبت في العطل: الحساب الحالي لا يراعيها.
- مراجعة صياغة قوالب التذكير والمستندات؛ الموجودة هيكلية وعليها `TODO(review)`.
- رفع نصوص القوانين من مصدر معتمد إلى المكتبة القانونية.

## النشر على Railway

الملفات جاهزة: [Dockerfile](Dockerfile) و[railway.json](railway.json). مستخدم Postgres الافتراضي في Railway هو superuser، وهذا يتجاوز كل سياسات RLS، لذلك **يرفض التطبيق العمل به**، ويتصل عبر دور محدود ينشئه [railway-release.mjs](scripts/railway-release.mjs) عند كل تشغيل قبل التطبيق.

1. أنشئ مشروعاً وأضف Postgres، ثم أضف خدمة من هذا المجلد.
2. اضبط متغيرات خدمة التطبيق:

```
MIGRATION_DATABASE_URL=${{Postgres.DATABASE_URL}}
APP_DB_PASSWORD=<كلمة مرور قوية طويلة، أحرف وأرقام>
DATABASE_URL=postgresql://reasonix_app:<نفس كلمة المرور>@${{Postgres.RAILWAY_PRIVATE_DOMAIN}}:5432/${{Postgres.PGDATABASE}}?schema=public
FIELD_ENCRYPTION_KEY=<مفتاح عشوائي، واحفظ نسخة منه بأمان>
INITIAL_LAWYER_EMAIL=<بريد المحامي صاحب المكتب>
INITIAL_LAWYER_PASSWORD=<12 محرفاً على الأقل>
ANTHROPIC_API_KEY=
WHATSAPP_TOKEN=
WHATSAPP_PHONE_NUMBER_ID=
WHATSAPP_APP_SECRET=
WHATSAPP_VERIFY_TOKEN=
NEXT_PUBLIC_OFFICE_PHONE=
NEXT_PUBLIC_OFFICE_WHATSAPP=
NEXT_PUBLIC_OFFICE_ADDRESS=
```

`NEXT_PUBLIC_*` تُقرأ وقت البناء، فأعد النشر بعد تغييرها. فقدان `FIELD_ENCRYPTION_KEY` يعني فقدان الأرقام الوطنية والملاحظات الخاصة نهائياً.

3. بعد أول نشر ناجح اضبط Webhook في Meta على `https://<النطاق>/api/whatsapp/webhook`.
4. **النسخ الاحتياطي اليومي**: أضف خدمة ثانية من نفس المصدر بأمر تشغيل `node scripts/backup.mjs` وجدول Cron `0 22 * * *`، مع `MIGRATION_DATABASE_URL` و`BACKUP_DIR=/backups` وVolume مركّب على `/backups`. الاسترجاع إلى قاعدة فارغة بعد الترحيلات: `node scripts/backup.mjs restore <الملف>`. النسخة غير مشفرة وعلى نفس المنصة، فانقلها دورياً إلى مكان آخر آمن.

التذكيرات تعمل داخل التطبيق كل 5 دقائق، فلا حاجة لخدمة طابور. هذا يفترض نسخة واحدة من التطبيق، وكذلك حد المحاولات.
